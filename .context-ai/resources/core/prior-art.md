# Prior-art decisions and design reconsideration

Compose [engineering](engineering.md) and [research](research.md). Source-supported interfaces establish what a component does; project policy decides whether to adopt it. A local trial establishes behavior in its stated environment.

Use PACT at consequential responsibility choices and HRR when reopening an existing design. Ordinary edits within a settled mechanism need no new landscape review. This is one workflow for both:

1. State the needed outcome, current owner and invariants. Trace an input through transformation, storage and downstream use. Identify duplicated policy, hidden dependencies and fields without a current consumer.
2. Inspect existing decisions and original evidence. Refresh only facts that can change the choice. Compare the current mechanism, strong relevant prior art and a smaller native or removal alternative on fit, authority, maintenance, license, privacy, compatibility, cost and removal.
3. Choose retain, adopt, adapt, bounded trial, build narrowly, remove or defer with a concrete trigger. Keep multiple options when contexts differ. A documented interface may justify a low-risk use; popularity does not settle fit and an efficiency claim needs an observation.
4. Perform a discriminating check and use the choice on actual work. Preserve requirements, retained data, edits and notices. Simplify responsibilities and prose; do not remove necessary failure behavior merely to reduce file count.
5. Obtain a bounded fresh challenge when useful, fix supported findings and rerun affected checks. Separate source authority, self-review, independent agent review and human use.
6. Record material rationale, supporting claims, applicability, uncertainty, result, rollback and revisit trigger in the existing decision/coverage structure. Send source-bound outcome feedback when it can change an assessment; reconsider at the next natural boundary.

Offering an option does not enable it. Keep selected, materialized, read/invoked and observed states distinct. Review a proposed refresh before replacing a running pin. Retain older exact records where a consumer needs them; Git can retain superseded prose. An honest unresolved gap needs a next action, not a confident recommendation.

Use native skills and review controls when available. Do not create an agent runtime, mandatory receipt per small edit, unrestricted interview or peer-readiness loop.
