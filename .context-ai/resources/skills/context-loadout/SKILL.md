# Equip the current task

Inspect the project's instructions, stack and intended outcome. Use the [command contract](../../docs/loadouts.md) to list/explain choices and plan a composition for this exact project and provider. Start with standard; select concern-specific additions only when relevant.

Review selected modules, capability states, sources, options, checks and planned paths. Missing required support fails; an optional browser tool does not prevent backend work. Resolve conflicts before application. A manifest grants no command, network, install or deployment authority.

Apply within the user's existing authorization. Preserve existing instructions and edited managed files. Pin the resolved lock for this stage; do not silently refresh an active run. Read only the resources routed to the current stage, then invoke relevant tools. A link or installed skill is not a read or invocation. Use one primary design procedure at a stage; brand/project decisions override advisory tastes.

Record a use receipt separately from installation: capability, source revision or lock digest, consumer/task stage, read/invoked/validated/not_used, discovery mode, result and command/artifact reference. Mark direct instruction reads as explicit-read when native discovery was not observed. Compare evidence and local outcomes before proposing a successor decision or refresh. Keep private runtime receipts local.
