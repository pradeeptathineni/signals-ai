# 0.3 validation and limits

The current product uses one Git JSON Corpus, a derived Pages view and private local JSON files.
All database services, containers, drivers and runtime commands are retired. Historical receipts,
screenshots, policies and implementation remain in their original Git commits; they are not current
product surfaces.

## Preservation and migration

All 83 retained database snapshots were exported into `.signals/retained/`: 981,522 rows, including
450,160 catalog rows. Every exported file's hash, row count and column inventory was checked.
Four representative typed restores preserved every canonical row and its multiplicity. Different
server collations affected row order; the proof compares complete row multisets, not ordered-stream
hashes. Project containers and exclusive volumes were then removed. Raw leads and old fixture
admissions remain historical data; they do not automatically pass the new public admission gate.

Previously published public evidence retains its exact schema-v1 bytes and digests. Two weak
findings were withdrawn at score 50 and replaced by narrower successors. Eight new or revised
findings passed a separately attributed agent review at 75. No exceptional score was awarded.
The score is min(relevance, evidence, usefulness, clarity) times 25; all four must be strong.
Source-backed capability and an actionable trial can qualify; measured superiority remains unknown.

## Actual concept questions

The retained Signals catalog supplies 134 definitions in `concepts.json`. The full catalog diagnostic
reports word matches and gaps without declaring a relevance pass. Eight questions selected from
actual concepts received separate source-aware review. With 20 admitted options, the useful candidate
ranked first in all eight sampled questions; some only partially answer the need. The every-word
filter matched only one full question. Ranked top-three/eight lists contained substantial irrelevant
items and must not be presented as reviewed answers.

| Need                                          | Useful first candidate          | Remaining boundary                                            |
| --------------------------------------------- | ------------------------------- | ------------------------------------------------------------- |
| Task-ranked repository context                | Aider code map                  | Rules, commands and hard budget not established               |
| Recoverable command output                    | CCA observations                | Normalized/redacted recovery; no general savings proof        |
| Relevant bounded code snippets                | Native Copilot semantic context | No enforced snippet cap or local-only guarantee               |

| Understand and review agent changes           | Human code-review precedent     | No measured agent-review effectiveness                        |

| Stable prefixes and verified cache reads      | Anthropic cache contract        | No provider calls, hit measurements or demonstrated savings   |
| Versioned model/application cases             | Promptfoo cases                 | Model grading is separate from deterministic checks and truth |

Two independently selected non-software needs—pothos watering and waterfall exposure—have primary
source-bound findings and visible limits. No user benefit or candidate execution was measured.

## Discriminating checks

Tests cover weak-dimension and unsupported-claim admission holds, exact digest/option binding,
fixture rejection, duplicate keys, cross-kind identity collisions, concurrent publication,
aggregate limits, expired admission, tampered retained history and interrupted exports. Due
evidence stays readable with visible dates; expiration does not disable unrelated knowledge.
Model fixtures check fabricated IDs, excluded-domain escape, rejected summaries, reviewer additions,
loopback-only routes, redirects and input/output budgets. These prove boundary behavior, not model quality.

Browser checks use real Corpus filtering, the shared literal/ranked modes, structured downloads,
two-option comparison, keyboard navigation, 320/1440 reflow, axe scans, corrupt/loading errors and
local question saving. Actual HTTP requests must deny private default/custom directories and
cross-origin writes. Automated accessibility does not establish comprehensive accessibility.

Independent review found and led to fixes for unsupported summary survival, identity collisions,
private-file serving and aggregate collection limits. Old database-only tests were removed with
their retired responsibilities; the current complete gate is `npm run verify`.

Context's narrower portable selection was applied to real Signals work, including this refactor
and guided UI review. Actual peer feedback distinguishes documented practice use from unexecuted
Testcontainers references. Later source challenges narrowed CCA recovery semantics. The file
exchange records exact source/composition pins; it does not substitute for human validation.

Before a stable release, configured-live model usefulness, repeated retrieval stability, broader
coverage and real human outcomes still need evidence. No test proves correct answers for every
possible question. The premature stable identity was withdrawn; 0.3 is a development milestone.
