# Observed web-guidance use

The audience is a local project owner/research agent. The job is to inspect cited evidence, make a
scoped decision and transfer an admitted revision. Existing Search/Corpus/map/compare flows and
the paper/forest visual system were retained. Exchange adds one coherent place for the missing
admit/export/refresh/feedback transitions.

Primary evidence is in [the real web bundle](web-foundation-2026-10-05.json) and its exact SHA-256
sidecar. Ten source-bound claims/options cover Agent Skills, Codex instructions/skills/config,
Impeccable, Vercel React guidance, frontend-design reference, WCAG, Playwright/axe, vitals and React.
Upstream revisions, locators, license observations and lineage are recorded in that bundle.
It is agent-assisted acquisition admitted by the actual application; no application-model run is claimed.

Impeccable revision `ece38d9904b8a619b3f77cab476eacad09c4fb11` was read selectively as a product/design/
critique method, using its actual distributed `.agents/skills/impeccable/SKILL.md`, shape and critique.
The installed binary/hooks were not required. Vercel React revision
`063bee94c3f4df8453406c830b0a7df0f2860278` supplied stack-relevant guidance; Next.js deployment advice
did not apply to React/Vite. Frontend-design remained a reference rather than a duplicate manifesto.

The first rendered Exchange buried exports below the options and used unstyled action buttons.
The critique moved export/digest/reassessment beside the evidence heading, reused existing button
styles, made producer confidence explicit, and kept optional lineage/feedback/readiness forms
collapsed. Source citation and uncertainty remain next to each option. The desktop library/detail
layout collapses to one readable column on narrow screens; long identifiers wrap without overflow.

Actual built application screenshots were inspected at 1440×1000 and 320×800, including lower
source/feedback areas. The before/after files and [check receipt](ui/checks.json) are under `ui/`.
There were no axe violations, page errors or horizontal overflow in that real-bundle sample.
Keyboard skip-link focus and reduced-motion support were checked. The separate browser regression
drives real import, review, download byte equality, readiness, feedback and unchanged reassessment.
Existing browser tests cover loading/setup/failure, cited detail, map/compare and historical synthesis.

Final built entry JavaScript was about 423 kB / 122 kB gzip, compared with the earlier observed
408 kB / 118 kB gzip. The existing optional G6 chunk remains lazy at 1.41 MB / 405 kB gzip; Exchange
does not load it. Build size is a lab observation, not a Core Web Vitals measurement. Field data and
Lighthouse scores were not collected for this private loopback app; SEO is not a local operational
acceptance gate. Browser interactions and accessibility checks provide limited relevant evidence.

This is builder visual review, not independent evaluation or human usability validation. It supports
a scoped instruction trial, not universal design superiority or proof that the guidance alone caused
the observed improvements. Reassess on a stack mismatch, changed upstream license/interface, a
regression or a better tested alternative.
